# 80. XeGTAO ambient occlusion, upscaler motion vectors and depth, SMAA T2x (Gears 2, Gears 3)

All of this is shared layer 0 (`Gears2-Native/src/layer0_xenos`), so Gears 3, Judgment and Gears 1 build it too
(s.11). Per-game settings are in `gow2_app.h` / `gow3_app.h`, the launcher option in `cogbox/`. Facts are marked
[V] verified, [I] inferred, as in the other notes. Frame and copy numbers are Gears 2 Title Update 6, ch2, frame 1500.

## 2. Gears 2's AO chain, and how it is found

**The frame [V]** (resolve and draw logs, 17 copies):
- Copy 0: scene depth (D24FS8, EDRAM base 0, pitch 1280).
- Copies 5-10: the AO chain on a half-res `k_16_16_FLOAT` target (EDRAM 1624, pitch 640). Its first draw is an MRT quad whose rt1 (8888, base 1808) is the half-res fog, used outside the chain.
  - Copy 6: x = moving-object mask, y = half-res linear depth. Copy 7: raw AO. Copies 8, 9: blurs. All to one address (the ping-pong).
  - A temporal quad reads this frame's ping-pong and last frame's final AO; moving meshes are stamped again; copy 10 goes to a **different address**: the final AO, also next frame's history.
- Copy 11: the motion-blur velocity (`k_16_16`, pitch 640). Copy 12: the HDR scene (where the upscalers hook in).
- With `AmbientOcclusion=False` copies 5-10 disappear and nothing else changes. Destination addresses move with the settings, so **detection never uses addresses**.
- No normal buffer: the base pass writes rt0 only. XeGTAO rebuilds normals from depth.

**Detection** (`AoNoteResolve`, from `ResolveColour`), by shape:
- an R16G16F target whose copy is half the scene's guest size (±8; ultrawide copies 275 rows as 280, s.8);
- the first address that gets ≥3 copies is the ping-pong, the next copy of that target elsewhere is the final AO;
- the chain is trusted only after **3 frames in a row** (`ao_chain_streak_`): a one-off false match at 4K once skipped another effect's work.

**The apply [V]** is the game's fog pass with AO folded in (`ps AC8AE1A05DCEEACE`, full screen into the scene, blend One / SrcAlpha): `scene' = scene * AO * T + fog` with UE3's black occlusion colour. So the game's AO is a plain multiply of the lit opaque scene, after all lights and before translucency and fog.

## 3. Camera and depth maths (`ao.h` / `ao.cpp`, `tests/layer0_ao_test.cpp`)

- **Camera [V]:** VS c0-c3 of the frame's first depth-writing draw into a full-size target, read as columns (`FromConstantsTransposed`). Camera-relative, Z-up, no translation; near 10, far infinite.
- **Depth is reversed-Z [V]:** guest depth = 1 − clip.z/clip.w, so linear depth w = −b / (depth − (1 − k)) with clip.z = k·w + b. Checked against the game's own half-res linear depth: median ratio 0.9994. The flip comes from the viewport's Z scale/offset, which is read per draw (`ViewportDepthMap`), not assumed, so games with normal depth work unchanged. Host depth holds guest depth × 0.5 (`float24_remap`), undone before use.
- **XeGTAO constants** (`MakeGtaoConstants`): depth unpack (mul −b, add 1 − k), tan(fov/2) from the lengths of the clip-x / clip-y rows (so any aspect works), NDC→view, pixel size. It refuses matrices with no perspective divide or no depth range.
- **The same test picks the scene camera for every game:** a candidate whose depth row is not proportional to its distance row is skipped. Gears 3's Raven's Nest draws a planar reflection first (perspective along −y, depth row a world plane: an oblique near plane); taking it had left the real scene unjittered (DLSS / FSR / XeSS / T2x did nothing) and XeGTAO without constants. Unit test "a planar-reflection camera is not the scene camera" uses the logged matrix.

## 4. XeGTAO in the game's own composite

- **Passes** (`xegtao_shaders.h`, ported from Intel's XeGTAO): a 5-level view-depth pyramid (R32F, one dispatch per level), the main pass (normals from depth; slices × steps per preset: low 1×2, medium 2×2, high 3×3, ultra 9×3), 1-3 denoise passes, a debug view. Fitted to the shared compute layout (16 root constants, t0-t3, u0-u1, no samplers): `Load`s instead of Gather / SampleLevel. Non-finite or non-positive distance counts as sky (no occlusion). Every preset's main pass is built at start, so F11 doesn't stall.
- **When:** at the **scene depth resolve** (copy 0). By the scene colour resolve the game has overwritten EDRAM depth base 0 through a 640-pitch 2xMSAA alias for its half-res effects.
- **The stand-in:** the chain's targets (pitch 640) stay at 1x under the 1120 scale threshold at every resolution, so packing XeGTAO into the game's 640x360 copy would waste it. At the final AO copy, `kXeGtaoPackCs` writes a **scene-size R16G16F stand-in** (x = XeGTAO, y = the game's y). For the rest of the frame `AoOverrideViews` rebinds any 2D fetch of that address and size to it, marked as scaled so the shader's texel maths stay in guest units. The binding ends when that address is copied again, and at frame end. The game's own copy still runs, so its history stays its own.
- **Proof it is replaced, not added [V]:** with the stand-in white (`--gow2_ao_show=none`) the static scene is pixel-identical to the game with `AmbientOcclusion=False`.
- **Skipping the game's chain** (`--gow2_ao_skip_game`, 1 draws, 2 copies, default 3): only while XeGTAO or "none" is shown, XeGTAO has run this frame, and neither the final AO copy nor the scene colour copy has happened yet.
  - Draws: only those whose **only** colour target is the chain's target and that write no depth or stencil. The chain's first MRT draw writes the fog (rt1) and must run: skipping it washes the picture out.
  - Copies: only to the chain's own ping-pong address (`ao_chain_pp_dest_`). The final copy runs, so the chain is still found.
  - **The chain is forgotten on the first frame it isn't seen** (`ao_chain_known_`). Gears 3 reuses that EDRAM target for post effects in cutscenes once the game stops drawing AO; skipping their draws and copies left a copy unmade and read later: a device loss (INVALID_CALL, page fault at VA 0).
- **Cost [V]** (renderer GPU time, ch2): 1x 0.96 ms with the game's AO, 0.93 ms with XeGTAO high and the skip; 2x 2.24 / 2.33 ms. **At 4K it is not "about the original"** (0.4.4, ch1, uncapped, median of frames 3000+, a high-end NVIDIA GPU): game's own 3.43 ms, XeGTAO low 3.79, high 3.94, ultra 4.69 with 3 denoise passes; high with 1 pass about 3.2. In Shagg's comparison XeGTAO cost about 5 ms a frame on an RTX 3080 Ti (225 -> 116 fps, Gears 2 act 1; the quality and resolution aren't recorded), so the launcher marks it experimental.
- **Denoise passes** (`--gow2_ao_denoise`, `ao::DenoisePasses`, default 0 = automatic): the passes, not the main pass, are most of the 4K cost (~0.35 ms each). Automatic: **under DLSS / FSR / XeSS by the size the scene is drawn at**, because their many-frame accumulation hides XeGTAO's noise less at low resolution: at ultra 3x or more 1 (no visible difference between 1 and 3 with DLSS at 4K in play), 2x 2, 1x 3; below ultra one more, up to 3. FSR and XeSS were not compared by eye. An upscaler asked for but unavailable counts as none; otherwise **3 at high and below, 2 at ultra**: under SMAA T2x's two-frame average, high shows grain under a chair with fewer than 3, while ultra's 9 slices start cleaner and 2 equal 3. A 6-slice ultra was tried and dropped: it needed the third pass again, which costs what the 3 fewer slices save. F8 cycles the passes live.

## 5. AO where the game has none: the multiply before the fog

- Gears 2 turns its AO off in some areas (outdoor parts of ch3, ch15) [V]: the frame then has no chain and a fog-only pass, `ps D58B286B84EE971D`, at the same point with the same blend.
- `AoAddWanted` / `AoAddPass` (`--gow2_ao_everywhere`, default on with `gtao`; anchor `--gow2_ao_fog_ps`): in a frame with no chain so far, just before a full-screen draw into one scene target (16-bit float or 10:10:10:2) with blend One / SrcAlpha and a listed fog shader, one full-screen triangle multiplies the scene by XeGTAO's AO (src Zero, dst SrcColor, RGB). That is the game's own apply formula, so the look stays continuous where it switches its AO off. Once per frame; never on a frame where a chain was seen; never into a multisampled target.
- Coverage [V]: every frame is either replaced or added, none both. A level with neither AO nor fog has no anchor.
- `--gow2_ao_add_radius` / `_add_power` (below 0: the main ones) make the added AO gentler where wanted (Gears 3, s.9).

## 6. DLSS / FSR / XeSS: depth and motion vectors

- **Reversed depth in the reprojection [V]:** `ReprojectionMatrix` now takes the viewport's depth map and undoes it; before, every pixel looked ~10 units away, so camera translation gave huge parallax (saturated vectors while strafing). Test "camera motion with a reversed-Z viewport".
- **The SDKs are told the depth is inverted:** DLSS `DepthInverted`, FSR `FFX_UPSCALE_ENABLE_DEPTH_INVERTED`, XeSS `XESS_INIT_FLAG_INVERTED_DEPTH`, from the viewport's Z scale; each wrapper rebuilds its feature when it changes.
- **Depth copied at the scene depth resolve** (`UpscaleSaveDepth`, `--gow2_upscale_depth_at_resolve`): as for XeGTAO (s.4), Gears 2 has cleared the scene depth by the colour resolve, so the motion pass and the SDKs had depth 0 everywhere (every pixel at infinity, where translation moves nothing). Falls back to the old read on the first frame and after a scale change. After the fix, block-matched image motion and the vectors agree within ~1 px [V]. Gears 3's depth is intact until the colour resolve (both points measured the same, s.9), so this is a Gears 2 default. Judgment has it on too (s.11). **Gears 3 keeps it off on purpose [V]** (2026-11-04): in Raven's Nest (ch1, a planar reflection pass before the view) the depth read at the colour copy is blank - one value for the frame - and the early copy gives a correct one; but on the ch12 airship (the camera moving 20-33 units a frame with the ship) real depth gives everything moving with the camera (deck, squad) the full translation parallax: vectors of 14-22 px instead of 2.6-3.9, 35-46% of pixels changing by > 1 px frame to frame, T2x / DLSS breaking up in patches (seen in the test window). With no depth, translation drops out and only the rotation is left, which is right for a moving platform. The real fix is per-object motion for Gears 3, as s.6 does for Gears 2's characters (s.13). **2026-11-07:** that is s.15; with it real depth works in Gears 3 too, both opt-in (`--gow2_upscale_object_motion_match=256 --gow2_upscale_depth_at_resolve=true`).
- **Characters' own motion** (`--gow2_upscale_character_motion`, Gears 2):
  - Gears 2's velocity pass draws every skinned mesh into the half-res `k_16_16` target (copy 11, blend MAX). Its values are not used (mostly 0.5 = "no velocity"); **only its mask is**: written = a character pixel.
  - Its draws carry VS c5-c8 = this frame's object-to-world relative to the camera and **c9-c12 = last frame's in absolute world coordinates**, so last frame's camera position = c12 − last frame's c8 of the same mesh (`PreviousCameraFromObjects`, median over meshes).
  - `VelocityDraw` collects the transforms (c0-c3 must be the scene camera, rows affine); `VelocityResolve` copies the mask (`kCopyFloat2Cs`) before the game reuses the EDRAM; `CharacterMotion` builds a table of ≤32 characters, each a reprojection (`ObjectReprojectionMatrix`) and an origin; `kMotionObjectsCs` gives each masked pixel the nearest character's reprojection within 250 units, others keep the camera motion. Upright (yaw-only) bodies are preferred over attached parts (gun, helmet), whose idle sway otherwise flickered the vectors of a still player.
  - Result [V]: characters' vector error 1-8 px (was 10-35 px with camera-only vectors); a still player gets exactly 0. Limb animation inside a mesh is not modelled. Test "characters move with their own transforms".
  - It never fires in Gears 3 (its object rows are c7-c10), so it is a Gears 2 default.

## 7. SMAA T2x

- An upscaler kind (`rr::upscale::Kind::kSmaaT2x`, `T2xUpscaler`, made in the renderer because it needs the shader cache), so it gets the scene-colour hook (before bloom, tone mapping and the HUD), the jitter, the depth copy and the motion vectors of s.6. Camera cuts reset the history. It works at the render size; the scene-resolution modes are ignored.
- Jitter: SMAA T2x's two positions, (0.25, −0.25) / (−0.25, 0.25) in NDC (y up), i.e. viewport offsets ±(0.25, 0.25).
- Passes (`smaa/smaa_passes.h`): `kT2xPrepCs` (an invertible tone map of the HDR scene and its square root for edge detection; a 10:10:10:2 scene skips the tone map), SMAA edges and blending weights with the sub-sample indices (1,1,1,0) / (2,2,2,0), neighbourhood blending into an RGBA16F ping-pong history, then `kT2xResolveCs`: last frame reprojected (manual bilinear), clamped to this frame's 3x3 neighbourhood, averaged 50/50 and tone-mapped back.
- Result [V]: standing still, the output changes ~10x less frame to frame than the jittered input; no double edges or trails mid-turn. Built-in shaders, so D3D12 and Vulkan. Cost at 4K (3x): about +0.5 ms over SMAA 1x, including the depth copy and the motion vectors.
- Gears 3 [V]: no new black triangles from the jitter (its half-res 4x MSAA translucency target, Gears 3 notes/14); characters get camera-only vectors there, which the 3x3 clamp limits to softness.

## 8. Ultrawide (`--gow2_ultrawide`, notes/57)

The scene is 1280x550 × scale; the AO chain and velocity are 640x275, copied as 280 rows (copy rectangles round up to 8). Two fixes [V]: the AO detection compares the copy with half the scene (280 vs 275, ±8), and the character mask's scale comes from the scene, not the copy. XeGTAO's tan(fov/2) gives 2.33:1 with no special case, and the AO follows the game's own profile across the width; background vectors match block matching within ~1 px at the edges.

## 9. Gears 3

- Gears 3 draws real-time AO in some levels only (ch1, ch12, parts of ch3: Gears 2's chain exactly); elsewhere (ch8) its AO is baked into the lightmaps and the AO switch changes no pass [V].
- Its fog pass is `vs ADB0FB487B4376A8 / ps 724AB5F143DBBFD4` into a 10:10:10:2 scene, the same shader in every level checked: `gow3_app.h` sets it as `gow2_ao_fog_ps`.
- Where the game has its chain, XeGTAO replaces it at Gears 2's strength; where it adds, `gow3_app.h` sets radius 35 / power 1.6, which keeps contact and character shading and drops most of the broad darkening the baked AO already has (ch8 mean AO 0.961 vs 0.934 at Gears 2's 60 / 2.2).
- The launcher offers the AO option and T2x for Gears 3 too. Character motion (s.6) does not fire there.
- The developer keys are installed in `gow3_app.h` as in `gow2_app.h`.

## 10. Multisampled targets and device losses

- Gears 3 draws effects through 4x MSAA views of the scene. Nothing of ours may touch a multisampled target: XeGTAO's depth input, the add pass's target and the upscalers' depth copy each refuse one and log once ("multisampled").
- The Gears 3 cutscene device losses (INVALID_CALL, VA 0) were the remembered AO chain of s.4: fixed by forgetting it on the first frame without it, and by skipping only the chain's own copies. Retested through the ch8 cave and the ch12 airship landing, where it had happened: no loss.

## 11. Other games, and per-game defaults

- Judgment and Gears 1 compile this layer 0 too. Gears 1 was not built or run in this work (its later fixes and AO: s.14); Judgment was for its DLSS fixes below. XeGTAO and T2x are off unless asked for. The launcher offers T2x for Gears 2 and Gears 3, and AO for Judgment too (notes/81).
- Gears 2-only behaviour is a default in `gow2_app.h` (only while the switch still has its compiled-in default, as `gow3_app.h` does): `--gow2_upscale_depth_at_resolve` and `--gow2_upscale_character_motion` are off in layer 0.
- Applied to every game: the scene-camera perspective test (s.3; Gears 1's own camera search already requires a perspective matrix) and the multisample guards (s.10), which only ever refuse work.
- XeGTAO is opt-in in both games' launcher option ("Game's own" by default).
- **Judgment's DLSS (2026-11-04, `gowj_app.h`) [V]**, built and run with scratch saves (SP_01_University_P):
  - **The scene copy.** Judgment copies its full-screen scene several times a frame: three mid-frame copies for translucency (guest colour format 10, `k_2_10_10_10_AS_10_10_10_10`, after draws 2235, 2293, 2555 of 2802) and the finished scene (after draw 2711), then bloom. The upscaler took the first, ~480 draws early: ~170 camera draws a frame came after it, unjittered and at render resolution (Ultra Performance: a mess, little AA). `--gow2_upscale_scene_last_copy`, on for Judgment: `rr::upscale::SceneCopyPicker` hooks the frame's last full-screen scene copy, its position learned from the frame before: 0 draws after the upscale, ~2,290 jittered a frame instead of ~990. Picking the copy by format does not work: the finished copy is format 2 in University but format 10 in Aftermath E2, where the upscaler then stopped.
  - **The depth.** Read at the scene colour copy it was one value for the whole frame (the EDRAM reused by then); distant edges broke up even at DLAA. `--gow2_upscale_depth_at_resolve` on for Judgment: a full depth image. Standing still, its motion vectors are exactly 0 and the jitter told matches the image shift.
  - **Result (hands-on):** DLAA clean on distant buildings; Ultra Performance acceptable. Its own AO still flickers under the jitter (gone with `AmbientOcclusion=False`): it is drawn at half resolution from the jittered depth (s.13). Untested: vehicle sections (the Gears 3 moving-platform limit above may apply).
- **DLSS Performance at 4K draws at full size [V]:** the renderer draws the scene at whole-number scales of 720p only, and Performance at a 3x output would be 1.5x, so it falls back to native with a log warning - 4K DLSS "Performance" is DLAA plus DLSS's cost, which may explain #150's frame rate [I]. Quality (3x -> 2x) and Ultra Performance (3x -> 1x) work at 4K; Performance works at 2x and 4x output. The launcher's tooltip says what Performance needs, but the choice can still be made at 4K.

## 14. Gears 1 (2026-11-07)

- **The light strobing over characters under DLSS [V].** Gears 1's first full-screen scene copy (16-bit float; about draw 613 of 780 in Prison) comes before its per-light passes: ~80 draws a frame into the scene depth with a depth test and no depth writes, some behind stencil shadow volumes (found by logging the jitter decision of every draw of a frame). Upscaled at that copy, they were drawn unjittered over the jittered depth and failed in patches that changed with the jitter phase. `gow1_app.h` now sets `--gow2_upscale_scene_last_copy` (s.11, as Judgment): 2 draws after the upscale, neither a perspective one; tester: "much better". `--gow2_upscale_jitter_late` cannot do it for Gears 1: it knows a draw by the camera block in c0-c3, and Gears 1's per-object matrices never equal it.
- **No camera on Tyro, the train [V].** Gears 1 takes its camera from a draw with identity object rows (the level's geometry, job 716). On the train everything is a placed object, so there was no camera: no jitter, no DLSS, no AO (0.4.7 too). Measured in Prison against the level geometry's camera: where c4-c7 is a perspective at all, it is the camera times the object's rotation only - no scale (taken with the full rows, the near plane came out as 10 x the object's scale) and no translation. After a frame with no identity-row draw, the camera is taken from the object draws: c4-c7 x R^-1 (R's columns normalised), voted over the frame's draws (clusters whose every column agrees within 0.3% of its size; the biggest cluster's mean). The train's first draw is a backdrop with its own projection (near ~15000), so the first draw alone was wrong. Tyro now: near 10.0 and the usual field of view on every frame. Levels with level geometry take their camera from it as before.
- **AO where Gears 1 has none [V]** (`--gow2_ao_add_at_scene_copy`, set by `gow1_app.h`). There is no scene depth resolve to run XeGTAO at (s.4) and no fog pass to anchor the multiply to (s.5), so at the frame's first full-screen scene copy XeGTAO / CACAO runs on the scene depth target and is multiplied into the scene. That copy comes before the per-light passes, so only the base pass's light (lightmaps, ambient) is darkened, not each light's own. Checked: AO on every frame in Prison, Embry, Caves and Tyro; a contact shadow under a ledge where the game draws none. Tester: "even CACAO low is a big improvement". The developer keys (s.12) are installed in `gow1_app.h`. The launcher offers the AO option for Gears 1 (found by the switch's description in the exe); Off and Game's own are the same there, so no ini edit. Strength: Gears 2's (radius 60, power 2.2), not tuned; the add path's gentler values (s.9) are the obvious comparison.

## 15. Object motion: draws matched by their object rows (Gears 3, 2026-11-07)

- **The problem [V]** (Gears 3 ch12's airship with real depth: DLSS's motion input captured exactly and every matching decision logged for six frames):
  - the deck is built from pieces sharing one identity (11-46 draws), placed around one pivot: the origin rule's distances tie at 0, the first unused piece wins, 28-180 px of false motion;
  - a single candidate was taken whatever its distance: the hull meshes have their origin behind the camera, and one frame put ~1300 px vectors on 67% of the deck;
  - the hull's pixel shader changes from frame to frame, so its identity does;
  - a match up to 0.25 NDC^2 (half a screen) was accepted.
- **`--gow2_upscale_object_motion_match=N`** (default -1, the 0.4.7 origin rule). The candidates are last frame's draws of the same index count and vertex shader, any pixel shader (the identity's own are preferred by 4 units). The score is the difference of the object rows: translation in world units (the rows are camera-relative, so a world-still object moves by the camera's travel, 10-30 units a frame on the airship) plus 512 x the largest difference of the normalised rotation; a rotation difference over 0.25 (~14 degrees) or a translation over N refuses. Gears 1 has no object rows and keeps the origin rule.
- **Moving status** follows the matched draw's identity when the draw's own is not moving.
- **The moving test** also probes five on-screen points, taken back into the mesh's space, when its origin and axis points are all behind the camera: the player's airship was never found moving before and got the camera's reprojection, 50-150 px.
- **Precision.** In float, an object's reprojection (prev_L x L^-1) is several pixels off for a mountain piece ~300000 units away, differently per piece and frame: the flicker on mountain silhouettes and between their components the tester saw. Now rows_prev x rows_now^-1 is taken in double (the large translation cancels to the small real move) and set between the two camera blocks. Checked by rebuilding the camera-only motion from the captured depth and the logged matrix (exact to 0.001 px where no object is drawn): the mountains now agree with it; only what rides the ship differs.
- **Results [V]:** deck motion 0-1.2 px (0.4.7: up to 1032 px); with the camera turning, ragged blocks 12-64% (30-91%) and vectors over 1000 px on 6.5-9% (up to 12%). Tester: "the mountains ARE fixed"; ch1 and fights on the ground good. Judgment with the switch: every draw matched (0.4.7 left ~120 a sequence unmatched), no wrong matches found, the look unchanged.
- **Defaults:** off in every game (-1 keeps 0.4.7's rule). Tested in Gears 3 with `--gow2_upscale_object_motion_match=256 --gow2_upscale_depth_at_resolve=true`; turning it on there by default is left to the maintainer.
- **Not motion:** distant fine detail (window frames) shimmers in motion in Judgment with every AA mode, SMAA worst - detail smaller than a pixel.

## 16. Soft shadows (PCSS) for Gears 3's dynamic shadows (2026-11-07)

- **The game's shadows [V]** (a depth-texture trace of whole frames in ch1, 8, 12; `--gow2_pcss_trace_frames`, Ctrl+Shift+F12 on the developer keys). Characters and moving objects render their shadow into one 1120x688 depth buffer (EDRAM base 1440, pitch 1120 - the EDRAM left after the scene, so the game cannot go bigger: `MaxShadowResolution=1120`, and each ch8 shadow already uses 1110x678), resolved to a k_24_8 texture and reused shadow after shadow. Light-volume boxes (`vs B5A1208D037C2F4F`, stencil) project them with one of three pixel shaders, all the same 9-tap 3x3 filter (soft comparison `saturate((d - receiver) * k + 1)`, k = `PerObjectShadowTransition` = 60, bilinear weights - about two texels wide everywhere):
  - `3C5E875D17B49A36`: into the light-attenuation buffer (most shadows), shadow map in slot 1, k in c7.z;
  - `CA3F4A808B09D6F4`, `857CECDEB64A657F`: modulated shadows (they multiply the scene), slot 2, k in c12.z / c14.z, the filter interleaved with the light's falloff.
  - The outdoor sun (`MaxWholeSceneDominantShadowResolution` 1344: a 1344x1344 map, pitch 1360, in ch5, 10, 21) goes through `3C5E875D17B49A36` too, sharpness 600.
  - The shadow matrix (receiver's view position -> shadow space) is in the constants: `3C5E` columns c8-c10 + c11 (depth in .z, u in .x, w in .w), `CA3F` c13-c15 + c16, `857C` c15-c17 + c18 (both depth .z, u .x, w .w). The sun and directional lights' per-object shadows are orthographic (no w row), spot lights' perspective (ch8); depth is linear in both (the receiver is not divided by w).
  - Not shadows: ch1's swinging submarine light throws a projected texture (light functions `FC367470036D7CFE`, `FE7BAA6C8F8E61B5`) - no depth compare, PCSS does not apply.
- **`--gow2_pcss=off|high|ultra`** (default off; launcher "Soft shadows", Gears 3 only, experimental). The three shaders are translated through the HLSL path with a text patch (`ApplyPcss` in `shader_cache.cpp`; a shape it does not recognise logs a warning and keeps the game's filter). The game's filter still runs; PCSS replaces its combined result before the fade / modulate maths, from the same receiver depth and shadow coordinate:
  - a blocker search (gathers of 4 texels) around the receiver; no blocker = lit, all blockers = the search's own average (deep shadow, no filter);
  - a penumbra in world units from the shadow matrix, then in the game's texels at the receiver (1 to 12 x the radius): orthographic = the depth gap (world) x a light angle (0.2 x the radius); perspective = (receiver - blocker) / blocker distance x a light size (40 world units x the radius), the distances from depth = alpha x w + beta. For the two orthographic map kinds this nearly equals the first version's 150 texels per depth unit (their depth range / texel size ratios are close); spot-light shadows change;
  - a spiral filter of that width with the game's own soft comparison, bilinear-weighted gathers, rotated per pixel (DLSS / T2x smooth the noise).
  - Presets: high = quality high (32 search texels, 16 filter gathers), radius 0.35; ultra = quality ultra (64 / 32), radius 0.25, and the shadow maps (pitch 1120 - in ch1, 3, 5, 8, 10, 12, 15, 18, 21 the only target that wide - and the sun's, pitch 1360, which #212 otherwise keeps at 1x) drawn at the scene's render scale. Distances are in the game's texels, so a scaled map gives finer samples, not a different shape. The game's filter on a scaled map pixelates (#212's sun shadow), which is why scaling belongs to PCSS.
- **One bytecode kind per pipeline:** the patched shaders are DXIL, the rest DXBC, so a draw pairing a DXBC vertex shader with them takes the vertex shader's DXIL twin (`ShaderCache::GetDxilTwin`, compiled once); the pipeline warm-up leaves such recorded pairs to the draw.
- **Cost [V]** (ch8, 4K DLAA, RTX 5090, per-draw GPU times over 4 frames, 35 projections a frame): the projection 0.25 ms with the game's filter, 0.70 ms high, 0.85 ms ultra; ultra's scaled shadow maps +0.11 ms. Before the gather search and the early-out: 1.38 / 2.28 ms; before the world-unit penumbra and the gather filter: 0.66 / 0.81 ms.
- **Developer:** F12 the game's filter / PCSS, Shift+F12 view (normal / split: left the game's, right PCSS / coverage), Ctrl+F12 quality, Alt+F12 radius (with `--gow2_ao_debug_keys`; the state reaches the shaders in `xe_sys1.z` / `.w`); `--gow2_pcss_mode`, `--gow2_pcss_quality`, `--gow2_pcss_radius` override a preset; `--gow2_renderer_hlsl_override_dir` replaces any shader's HLSL from files.
- Tester: dynamic shadows look right in ch1, 8 and 12, preferred over the game's; the gather filter's edges "somewhat improved" (ch8); ch10's sun shadows look like ch8's.
